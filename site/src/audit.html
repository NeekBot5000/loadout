What we found reading every file in 160 skill repos

October 2026. To build the Loadout catalog we took the 160 most-starred GitHub repos tagged for Claude or agent skills, pinned each to a commit, and read every file in every skill folder as data, without running anything. Static rules flagged lines; a person read every serious hit in the repos that made it in. The method, the rules and every decision are in the repository.

Most skills are not what the folder count suggests

The biggest reason a skill folder did not become a catalog entry was not danger. It was that it was not a standalone skill: 118 were copies written for other agents (Codex, Cursor, OpenClaw and others), 64 only work inside their plugin because they read files the plugin provides, 33 were test fixtures or examples, and 5 loaded files from outside their own folder. Install any of those on their own and they fail, quietly.

What the safety rules flagged most

On the first pass, the most common high-severity hit by far was a symbolic link inside a skill (467 skills, nearly all in one large collection). Then: piping a download straight into a shell (87), text telling Claude to ignore instructions (43), webhook or paste-site URLs (42), text about keeping something from the user (28) and paths where secrets live (28).

Reading the hits changed the picture. Most "ignore previous instructions" lines were the opposite of an attack: skills telling Claude to treat web pages as data and refuse instructions inside them. Most install-and-run lines were quoted from vendors' own install pages in documentation. Several "secrets" hits were security tools describing what they detect. Rules find lines worth reading; they do not make the call.

What was actually left out

  • Three repos whose scripts read your browser cookies (and in one case the macOS Keychain) to act as you on other sites. Deliberate, documented, and still more access than a one-click install should grant.
  • One framework whose skills run hook scripts from outside their folders, so they break one by one.
  • Three repos with no license GitHub recognizes, until someone checks the terms.
  • Offensive security collections, which contain credential-access and persistence tooling by design.
  • One skill that writes Claude Code settings turning on bypass permissions.
  • A showcase repo whose skills point at that project's own files, and two repos with nothing installable left after the checks above.

Names collide

Skills install into ~/.claude/skills/<name>, so two skills with the same name cannot both be installed. Eight names in the catalog exist in more than one repo, for example test-driven-development and skill-creator. Loadout lists both and marks the second "Name taken" once one is installed.

Limits

This is a careful read of one commit per repo. It does not prove a skill gives good advice, and a rule only finds what it looks for. Repos change, so the catalog pins each skill to the commit that was read and shows a diff before any update.

Practical version: a checklist for reading a skill before you install it.
