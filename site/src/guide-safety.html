Is this skill safe to install?

Updated {{DATE}}. A skill is text that Claude follows, plus any files next to it. Some of those files are scripts that Claude may run on your computer with your permissions. Here is what to read before you install one, drawn from checking every file in {{SCANNED}} popular skill repos.

1. Read the whole SKILL.md, not the summary

The description says when the skill is used. The body says what Claude will do. Look for instructions that work against you: telling Claude to ignore your earlier instructions, to keep something from you, to skip asking before it acts, or to turn off permission checks. Be careful with the word search here: many good skills contain the phrase "ignore previous instructions" because they tell Claude to resist it in web pages. Read the sentence around it.

2. List the scripts

About a quarter of the skill folders we found contain files that can run code: .py, .sh, .js, .ps1 and files that start with #!. That is often fine (a PDF skill needs a PDF library), but each one deserves a look. Check what it imports and what it touches.

3. Follow the network calls

Search scripts for requests.post, fetch(, curl, Invoke-RestMethod and URLs. Sending data to the service the skill is about (an image API, your own app) is expected. Sending it to a webhook, a paste site or a bare IP address is not.

4. Watch for secrets

Red flags: reading ~/.ssh, ~/.aws, .netrc, the macOS Keychain, or browser cookie databases. Some popular skills read your browser cookies on purpose, to act as you on a website. That can be a deliberate feature and still be more access than you want to give.

5. Don't run installers you did not choose

curl ... | sh and irm ... | iex download a script and run it at once. Quoted from a vendor's own install page in documentation, that is common. Inside a script the skill runs, it means code you never saw.

6. Check the folder itself

  • Links. A symbolic link can point outside the skill folder. We found hundreds, mostly in a few large collections.
  • Hidden text. Unicode tag characters and bidirectional overrides can hide words from a reader. Zero-width spaces are usually harmless.
  • Files outside the folder. Skills that load ../../hooks/... or ${CLAUDE_PLUGIN_ROOT} belong to a larger project or plugin and break when installed alone.
  • Settings changes. A skill that edits ~/.claude/settings.json or turns on bypass permissions should say so plainly and ask first.

7. Pin what you checked

A repo can change after you read it. Install from a specific commit and review the difference before updating. Loadout installs community skills at the commit its audit read, and shows a file-by-file diff before any update.

The full list of what the Loadout catalog left out, and why, is in the audit report. See also what we found in 160 skill repos.
