How Claude Code loads skills, and what they cost

Updated {{DATE}}. Facts here come from the Claude Code skills documentation and the changelog; the numbers about the catalog are our own.

The listing

A skill is a folder with a SKILL.md file. Claude does not read every skill at the start of a chat. It reads a listing: every skill's name and its description. When a request matches a description, Claude opens that skill's full instructions. So the description is what makes a skill get used, and it is also what the skill costs you in every chat, whether you use it or not.

Each entry's text is capped at 1,536 characters. The whole listing has a budget of 1% of the model's context window. When the listing is over budget, Claude Code keeps every name but drops descriptions, starting with the skills you use least. A skill without its description is much less likely to be picked up on its own.

How fast it fills

Across the {{SKILLS}} skills in the Loadout catalog, the median description costs about 72 tokens and the longest about 390 (our estimate: characters divided by four). Turning all of them on would put about 108,000 tokens of descriptions in the listing, far past 1% of any current context window. Even 25 to 30 typical skills reach a couple of thousand tokens. You do not need a big collection to hit the limit; a few long descriptions will do it.

Four states, not two

Claude Code reads a skillOverrides setting (it works from version 2.1.129). Each key is a skill name and each value is one of:

ValueWhat happens
"on"Name and description are listed. The same as leaving the skill out of the setting.
"name-only"Only the name is listed. The skill still works when you ask for it by name, for a few tokens.
"user-invocable-only"Hidden from Claude, still in your / menu.
"off"Hidden from Claude and from the menu. The files stay where they are.

Name only is the useful middle ground for skills you call deliberately, such as a release checklist, while skills you want Claude to reach for on its own stay on.

Ways to manage it

  • Claude Code's own /skills menu cycles a skill's state with Space and saves it to .claude/settings.local.json.
  • /doctor estimates the listing's size and its biggest entries; /skill-doctor finds skills you never use.
  • To give the listing more room, raise skillListingBudgetFraction (for example 0.02 for 2%).
  • If you write skills, put the key use case first in the description, since long ones get cut.
  • Loadout shows the cost of every skill before you install it, keeps a meter against a target you set, and saves whole setups as profiles, writing the same skillOverrides setting.
